# 核心代码导读

检测程序的一帧流程是：取相机最新图像，整理成模型输入，运行NPU，还原检测框，交给FPGA判断告警，最后更新画面和记录。

## 板端主循环

从worker.py的main开始读。Latest只保留相机最新帧，避免旧图排队。NPU类启动一次C++子进程，之后反复发送图像、等待结果。拿到完整检测结果后，Hardware.commit把帧号和原始框交给FPGA，再读回告警状态。

显示和编码由MediaSink处理。它们使用容量有限的队列，来不及显示时覆盖旧预览，不拖住检测。日志按大小轮换，停止时先收完当前推理，再关闭SDK和编码器。

## NPU与图像整理

product_stream.cpp负责模型加载和推理。FusedStreamPicPre.hpp把BGR转RGB与补边合成一次处理；640×480输入在下方补160行，得到640×640张量。DirectTensor.hpp用于减少重复拷贝。

厂商模型图包含DetPostZG节点，CPU仍负责坐标解码和NMS。这里的NPU调用包含厂商配套推理逻辑；项目的FPGA告警模块处理最终检测框，不做神经网络计算。

## FPGA告警

先看region_alarm_regs_m505.v，再看region_alarm_core.v。前者把一帧的坐标收齐，判断框中心是否在ROI内；后者按帧号和连续观测更新告警。当前配置为连续3次命中置位、连续8次无命中解除，提交中断1秒则报告fault并保留原alarm。

CPU提交的是检测框和帧号，LED亮灭由FPGA决定。跟踪器用于画面关联，短时保留的旧框不会作为新检测送去告警。黄色轨迹只在素材演示版本绘制，相机实测版本显示框、编号和旧标记。

## 启动与上位机

run_camera.py由systemd服务启动，等待相机后开启检测。session_retention.py负责清理已结束会话，保留数量有上限；运行中的设备锁用于避免同时打开NPU。

Desktop.cs显示画面、FPS、告警和记录，agent.py执行SSH操作。查看画面走只读HTTP，启停走SSH密钥认证。私钥保存在使用者自己的电脑上，不随源码提交。

## 扩展与测试

reference/model11_training保留模型11的样本整理、训练和开发集计分程序，reference/model11_conversion保留导出与转换入口。训练脚本中的原实验目录、阶段计划和时间限制见各目录说明；日常运行直接使用现有模型文件。

reference/ir_deployment包含独立IR模型的部署程序，采用上下各64行补边。reference/pl_pixel保留FPGA像素处理和DMA代码，ps子目录是配套的CPU侧缓冲区、驱动和耗时比较程序。

tests/pl是告警仿真，tests/comparison是同任务CPU/FPGA比较；tests/board是需要真实板卡的定向实验入口。构建、仿真与现场运行分别进行，普通看代码不需要打开设备。
