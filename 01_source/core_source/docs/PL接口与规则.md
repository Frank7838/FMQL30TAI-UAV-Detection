# FPGA业务接口与规则

物理基址`0x400C0000`，签名`0xA5050001`。原生接口把写地址和写数据合并握手，不应按完整AXI4-Lite解释。所有偏移为字节，寄存器32位、小端。

|偏移|读写|意义|
|---|---|---|
|0x00|写|值1请求业务软复位；日常worker禁止使用|
|0x04|写|BEGIN，数据为32位帧号；重开未结束事务增加协议错|
|0x08|写|左上角：低16位x0、高16位y0|
|0x0C|写|右下角：低16位x1、高16位y1；必须与左上角成对|
|0x10|写|COMMIT：bits15:8为框数，bit0为fresh，其余位为0|
|0x20|读|状态，见下表|
|0x24|读|最后接受帧号|
|0x28|读|接受计数|
|0x2C|读|拒绝计数|
|0x30|读|协议错误计数|
|0x34|读|锁存事件|
|0x38|写|事件按位写1清除，同时到来的新事件保留|
|0xC0|读|ABI签名|

|状态位|意义|
|---|---|
|bit0|alarm|
|bit1|fault|
|bit2|have_frame|
|bit3|保留0|
|bits7:4|连续命中计数，饱和3|
|bits11:8|连续无命中计数，饱和8|
|bit12|事务影子命中状态hit，可能随未提交事务变化；不应单独用作已接受结果|

事件bits0到3依次为告警置位、告警解除、故障进入、有效新提交恢复。`switch_snapshot`依次读签名/状态/末帧/接受/拒绝/协议错/事件；保留每次MMIO屏障及读取前后的所有者检查，仍不是硬件原子快照。

框坐标为0到65535的归一化数值。默认ROI为`[8192,57344) × [4096,57344)`，按框中心判断，使用两倍坐标比较避免除2；一次完整提交内最多16框，任一合法框命中即为本帧命中。

连续3个有效区域命中置位，连续8个有效无区域命中解除。这两个数字继承早期经验防抖方案，不是赛题规定，也没有证明最优。计数不要求同一轨迹ID；持续背景误框仍能触发。未知、无效、过期、重复输入不能作为无目标来清警。

若没有有效新提交达1000ms，置fault、清连续计数，**保持上次alarm**。下一完整新鲜帧解除fault，但不会无条件解除alarm。若原先未告警，断流也不会凭空置alarm；fault同时送到LED1，alarm送到LED2。两灯可以同时亮：表示已经告警，但当前没有有效新结果。正常停止检测后，LED1也会在约1秒后亮起；这是结果超时指示。

当前修复丢弃故障入口之前未完成的事务，并给故障已存在时新开的事务独立超时。超时边界屏蔽写握手和尚未生效的commit，防止迟到COMMIT伪装成新鲜结果解除fault。`bus_reset`只清传输半事务；业务alarm与计数不随厂商NPU软复位清零。

告警保持依赖开发板供电与业务时钟；3/8对应的时间随有效推理频率变化。


## 硬件事件记录

OBS1观察模块不改变告警判断。置警、清警、断流、恢复各保存最近一次64位周期数和32位帧号，存储大小固定。周期从业务硬件复位开始计数，100MHz下一个周期为10ns，换算秒时除以100000000；它不是电脑时间，也不表示物理响应测量达到10ns精度。

|偏移|内容|
|---|---|
|0x40|OBS1签名0x4F425331|
|0x44|业务时钟频率100000000 Hz|
|0x48 / 0x4C|当前周期数的低/高32位|
|0x50|事件更新序号|
|0x54 / 0x58|有效记录位 / 最近事件位|
|0x60 / 0x64|置警周期数低/高位|
|0x68 / 0x6C|清警周期数低/高位|
|0x70 / 0x74|断流周期数低/高位|
|0x78 / 0x7C|恢复周期数低/高位|
|0x80 / 0x84 / 0x88 / 0x8C|置警 / 清警 / 断流 / 恢复对应的帧号|

软件在同一事件序号内读取低高位，通常每秒更新一次，出现事件时立即更新。状态、逐帧记录和结果文件中的hardware_observability保存这些信息。NPU的总线复位和事件清除不重置这个计数，正常停止也不会清掉已有记录。
