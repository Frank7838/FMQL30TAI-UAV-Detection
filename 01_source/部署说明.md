# 使用与部署

## 现有板卡与上位机

接好相机、电源和网线，板卡通电后自动检测。Windows电脑复制整个02_runtime/Windows/UAVDetectionSystem目录，运行无人机检测系统.exe。程序自带认证组件，使用Windows 10/11 x64及.NET Framework 4.8，通常不用另装Python。

网线有两种接法：直接连接电脑，或接入路由器。直连时板端为169.254.74.247/16，电脑可设为169.254.74.246/16；接路由器时，让电脑与板卡处于可互通的网段，连接设置填板卡实际地址。画面端口均为8080。第二台电脑的迁移与完整操作检验已经通过。

上位机由本项目制作，提供实时画面、帧率和运行状态、告警记录、暂停预览、保存画面、记录导出及启停操作。暂停预览或关闭电脑不影响板端检测。

启停通过SSH密钥认证。授权电脑保管私钥，板端登记公钥；新电脑设置私钥的本机路径并核对板卡主机指纹。私钥不随提交材料公开。正常停止会等待当前推理结束，再关闭SDK并释放设备。

## 提交目录怎么读

01_source是展开的带注释源码、构建和测试入口。02_runtime是现成上位机及板端运行文件；03_model保存模型11原权重和数据集来源；04_fpga保存当前BOOT、位流及报告。这四部分对应代码、软件、模型和硬件。

05_evidence集中主要实测结果。根目录是技术文档、AI说明和海报；06_ai-evidence保存AI使用证据；07_existing_media是演示视频及照片；08_licenses_and_notices是第三方来源。09_architecture放架构图，代码辅助阅读.html提供可点击的离线代码导读。

数据集不上传。视频中的NPU演示、实物照片及傍晚实测属于作品展示素材，来源和用途单独说明。旧定向验证图片留在本地，不放入运行交付包。

## 另一块同型号开发板与空白SD卡

模型图和参数可以复用，不必重新训练、导出或量化。但当前提交目录不是完整SD系统镜像：还需要匹配的厂商Linux系统、运行库和板级工程。新系统上的设备锁也需要重新绑定。

1. **先准备平台环境。** 使用与FMQL30TAI悟净开发板完整版匹配的厂商SD/Linux系统，包含内核、设备树、根文件系统及相机驱动。板端需要AArch64环境、Python 3、NumPy、OpenCV、v4l2工具、FFmpeg配套库，以及Icraft 3.39与ZG330运行库。源程序当前查找运行库的目录为/root/fpga_gaming/m7_20261002_01/runtime_339，部署时需准备该布局或同步调整配置。
2. **装入匹配硬件。** 04_fpga/current_BOOT.bin为现用启动文件，包含与告警寄存器匹配的硬件逻辑；它不包含整个Linux系统。确认硬件版本和启动布局后再写卡，保留厂商系统所需的其他启动文件。当前板卡的BOOT、分区和Flash不在普通软件安装步骤中修改。
3. **准备应用目录。** 将02_runtime/board/payload放到/root/fpga_gaming/model11_standalone_20261025_v1。当前payload已经合入会话清理、含boot的会话名以及硬件事件读取，不必再套旧补丁。模型实际运行文件为model/drone11n_ZG.json与.raw，NPU程序为product_stream。模型11原始.pt用于保存训练成果，不直接在板端推理。
4. **适配新文件系统的设备锁。** 当前worker.py、session_retention.py、ProductGuard.hpp和mmio.c绑定了原系统锁文件的inode 943514。新系统需在没有NPU会话运行时建立自己的独占锁，记录真实身份并同步修改这四处绑定；随后按源码构建说明生成product_stream和libswitch_mmio.so，并生成匹配的PAYLOAD_SHA256.json。原卡运行时不能删除重建锁文件。设备锁适配必须针对实际系统完成。
5. **先做一次前台运行。** 配好相机和网络后，从应用目录运行`python3 -B run_camera.py --seconds 60 --frames 0 --video-frames 120 --qualification-probe`。检查有画面、推理与FPGA提交正常，程序结束后SDK已关闭。这项短测直接使用相机，不依赖已移出的定向验证图片。
6. **安装自启与查看服务。** 将01_source/core_source/src/board/systemd里的model11-link.service、model11-viewer.service和model11-detect.service安装到/etc/systemd/system，执行daemon-reload并启用这三项服务。为授权电脑登记SSH公钥，配置板卡地址，启动服务检查上位机画面。
7. **人工验证通电自启。** 保持相机和网线连接，人工断电再上电，确认没有电脑启动命令时也能检测和告警，再做启停与持续运行检查。

如果只是同一块板更换SD卡，停机后离线复制已验收的整卡镜像通常更省事，也能保留原系统布局。迁到另一块板时，还应分别配置网络地址和SSH身份。当前没有对空白卡完成一键部署验收，以上明确列出了需要适配的部分。

## 最终版本核验

当前完整版本相机连续运行3600.122秒，107396次推理、107396次有效FPGA提交，整段平均29.831 FPS，未知0，SDK正常关闭。测试后检测停止、SDK关闭，持续自启配置已恢复。硬件事件为业务时钟相对时间，每类保存最近一次，LED1显示结果超时，LED2显示目标告警。


审核副本已清除设备专用默认主机指纹并重新构建上位机；SSH控制组件已完成离线自检。首次使用时须填写经核实的板卡指纹和本机私钥路径，重新构建后的上位机尚未进行实际连板验收。
